# AI Vacancy Fit Analyzer — Workflow v0.5

## Статус

Workflow реализован как ручной no-code MVP и отдельный Telegram MVP в Make. Router, технические фильтры, AI-ветка, fail-closed QA gate, Telegram trigger и доставка `MANUAL_REVIEW` фактически протестированы. Автоматическое извлечение данных и сохранение в Google Docs пока не реализованы.

Подробности реализации и execution evidence: [`MAKE_MVP.md`](MAKE_MVP.md).

## Реализованный Make MVP

```text
Tools: Set multiple variables
        ↓
Router
   ├─ vacancy_text = emptystring
   │  OR candidate_data = emptystring
   │      ↓
   │  error_message
   │
   └─ vacancy_text ≠ emptystring
      AND candidate_data ≠ emptystring
          ↓
      validation_status
          ↓
      Make AI Toolkit: Simple Text Prompt
          ↓
      QA Router
         ├─ известный запрещённый паттерн → qa_status = FAIL
         └─ fallback → qa_status = MANUAL_REVIEW
```

Фактические результаты:

- пустой `candidate_data` → fallback выполнен, AI заблокирован, `2 operations`, `2 credits`;
- оба input заполнены → AI выполнен, fallback заблокирован, `3 operations`, `3.31 credits`;
- scenario оставался `Inactive`, расписание было выключено;
- использован встроенный Make AI Provider без внешнего API-ключа;
- добавлен детерминированный QA Router без второго AI-вызова;
- автоматический `PASS` не присваивается: известное нарушение даёт `FAIL`, отсутствие совпадений — только `MANUAL_REVIEW`;
- обе QA-ветки фактически протестированы и оказались взаимоисключающими.

## Цель

Получать данные вакансии и кандидата, проверять их техническое качество и смысловую достаточность, проводить доказательный AI-анализ, формировать два независимых решения, выполнять QA и доставлять результат пользователю.

## Trigger

В текущем MVP Telegram-бот получает обычное текстовое сообщение с вакансией. Приём ссылок запланирован, но ещё не реализован.

Trigger запускает workflow, но не является входными данными.

## Входные данные

- данные вакансии: ссылка, текст или читаемые скриншоты;
- данные кандидата: ссылка на резюме, текст, файл, читаемые скриншоты или сохранённый подтверждённый профиль;
- ограничения кандидата;
- промпт AI Vacancy Fit Analyzer v1.2.

## Основной workflow

### Action 1 — получение данных вакансии

1. Открыть страницу вакансии по ссылке либо получить текст или читаемые скриншоты от пользователя.
2. Извлечь читаемый текст вакансии.
3. Не считать пустую страницу, сообщение об ошибке или страницу авторизации текстом вакансии.

### Action 2 — получение данных кандидата

1. Открыть ссылку или файл резюме либо получить текст или читаемые скриншоты.
2. Извлечь читаемые данные кандидата.
3. Использовать только подтверждённые факты; не выводить навыки из названия должности.

### Condition 1 — техническая успешность извлечения

Проверить отдельно:

- удалось ли получить читаемый текст вакансии;
- удалось ли получить читаемые данные кандидата.

Если любой набор технически не получен, не запускать полный AI-анализ и перейти к соответствующей ветке error handling.

### Condition 2 — смысловая достаточность

После успешного извлечения проверить отдельно:

- достаточно ли данных вакансии для доказательного анализа;
- достаточно ли подтверждённых данных кандидата для сопоставления.

#### Данных достаточно

Передать оба набора данных в AI-анализ.

#### Данных недостаточно

1. Не запускать полный AI-анализ.
2. Перечислить пользователю недостающие сведения.
3. Если не хватает условий вакансии, подготовить конкретные вопросы работодателю.
4. Если не хватает данных кандидата, задать конкретные вопросы пользователю.
5. При необходимости провести только ограниченный предварительный анализ доступных фактов, явно отметить неизвестное и не изображать окончательный результат.
6. После получения ответов повторить проверку достаточности.

Отсутствие зарплаты, формата работы или характера звонков в читаемом тексте — это не автоматически техническая ошибка. Это неизвестные условия, которые нужно явно отметить и уточнить.

### Action 3 — AI-анализ

1. Сопоставить требования и условия вакансии с подтверждёнными данными кандидата.
2. Для каждого вывода указать категорию доказательства:
   - прямое доказательство;
   - переносимое доказательство;
   - предположение;
   - недостаточно информации.
3. Не выдумывать опыт, навыки или условия вакансии.
4. Сформировать два независимых решения.

### Condition 3 — холодные звонки

- Если холодные звонки подтверждены, отметить стоп-фактор.
- Если формулировка неоднозначна, отметить риск и подготовить конкретный вопрос работодателю.
- Если холодные звонки не указаны, не придумывать их и продолжить анализ остальных условий.

Фраза «холодные звонки не указаны» не означает, что их подтверждённо нет.

## Решения

### Стоит ли отправлять отклик

1. Дать одну рекомендацию: `откликаться`, `откликаться при определённых условиях` или `не откликаться`.
2. Обосновать её подтверждёнными совпадениями, пробелами и рисками.
3. Указать следующие действия: подготовить отклик, написать сопроводительное письмо, уточнить условия или рассмотреть другие вакансии.

### Стоит ли принимать предложение

1. Дать одну рекомендацию: `можно принимать`, `принимать при определённых условиях`, `не принимать` или `пока недостаточно информации`.
2. Проверить критичные условия: зарплату, характер звонков, формат работы, обязанности и обязательные требования.
3. Обосновать решение подтверждёнными данными.
4. Указать, что нужно сделать или уточнить до окончательного решения.

Неизвестные зарплата или характер звонков не запрещают отклик, но могут сделать принятие предложения преждевременным.

## QA анализа

Перед сохранением проверить:

- каждый вывод основан на тексте вакансии или подтверждённом факте о кандидате;
- прямые и переносимые доказательства не смешаны;
- неизвестные сведения не выдуманы;
- подтверждённые стоп-факторы не скрыты;
- решения об отклике и принятии предложения разделены;
- для каждого решения есть вердикт, причина и следующее действие.

QA оценивает качество анализа, а не соответствие кандидата вакансии.

Статусы QA:

- `PASS` — обязательные правила соблюдены;
- `CONDITIONAL PASS` — есть исправимые пропуски;
- `FAIL` — скрыт стоп-фактор, выдуман опыт или пропущен критичный факт.

## Результат

1. Сохранить готовый анализ в Google Docs или другом основном хранилище.
2. Отправить пользователю ссылку на документ или готовый файл.
3. Если полный анализ не выполнен, сообщить, каких данных не хватает и что нужно предоставить.

## Error handling и fallback

### Страница вакансии временно не отвечает

1. Подождать и выполнить ограниченный retry открытия или извлечения.
2. Если повтор успешен, продолжить основной workflow.
3. Если ошибка сохраняется, сообщить пользователю, что текст вакансии получить не удалось.
4. Запросить текст вакансии, читаемые скриншоты или другую рабочую ссылку.
5. Не запускать полный AI-анализ до получения данных.
6. После получения данных повторить техническую проверку и проверку достаточности.

### Данные кандидата технически не извлечены

1. Сообщить пользователю, что данные кандидата получить не удалось.
2. Запросить файл, текст или читаемые скриншоты резюме.
3. Не запускать полный AI-анализ до получения данных.
4. После получения данных повторить техническую проверку и проверку достаточности.

### Текст извлечён, но данных недостаточно

1. Не выдавать отсутствие сведений за техническую ошибку.
2. Не выдумывать недостающие сведения.
3. Перечислить неизвестные условия и ограничить выводы доступными фактами.
4. Подготовить вопросы нужному адресату: работодателю — об условиях вакансии, пользователю — об опыте кандидата.
5. Допускать только ограниченный предварительный анализ доступных фактов с явной маркировкой неизвестного.
6. Запустить полный анализ только после прохождения condition достаточности.

### AI-анализ готов, но сохранение не работает

1. Не повторять открытие страницы, извлечение данных, AI-анализ и QA.
2. Выполнить ограниченный retry только операции сохранения.
3. Если повтор не помог, сохранить уже готовый анализ в `.txt` или `.md`.
4. Отправить fallback-файл пользователю.
5. Сообщить, что Google Docs временно не обновлён.
6. Позже можно повторить только сохранение в Google Docs.

## Схема

```text
Trigger: бот получил сообщение
        ↓
Inputs: вакансия + данные кандидата
        ↓
Получить и извлечь оба набора данных
        ↓
Техническая проверка
   ┌────┴────┐
   нет       да
   ↓         ↓
Fallback   Проверка достаточности
             ┌────┴────┐
             нет       да
             ↓         ↓
        Запросить     AI-анализ
        данные          ↓
                   Два решения
                        ↓
                       QA
                        ↓
                 Сохранить результат
                        ↓
                 Отправить пользователю
```

## Telegram MVP — фактическая архитектура

```text
Telegram Bot: Watch Updates
  ↓
Filter: Message.Text Does not start with "/"
  ↓
Set multiple variables
  vacancy_text ← Telegram Message.Text
  candidate_data ← сохранённый профиль
  ↓
Input Router → AI → fail-closed QA Router
  ├─ Missing input → Telegram error
  ├─ Known violation → Telegram FAIL
  └─ fallback → Telegram MANUAL_REVIEW + AI Answer
```

Команда `/start` была реально остановлена перед `Tools` и AI. Полный E2E run обычного текста прошёл через `MANUAL_REVIEW` и доставил ответ в Telegram:

```text
11 seconds
6 operations
6.94 credits
8.7 KB
```

Telegram-доставка `Missing input` также подтверждена: менее секунды, `4 operations`, `4 credits`, `1.3 KB`; AI не запускался. Отдельный Telegram E2E-тест доставки `FAIL` ещё не выполнен. Подробности: [`TELEGRAM_MVP.md`](TELEGRAM_MVP.md).
