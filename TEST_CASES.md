# Test Cases — AI Vacancy Fit Analyzer

## Test case 1 — Координатор в отдел ИТ

**Источник:** реальная вакансия hh.ru, компания «Сеть аптек Апрель».

**Цель:** проверить, не выдаёт ли анализатор переносимые навыки за прямое соответствие.

**Проблемы v1.0:**

- координация команды была слишком близко приравнена к межотдельской координации;
- знание Excel было приравнено к MS Office;
- клиентский опыт использовался как подтверждение работы с жалобами.

**Ожидаемый результат v1.1:** явно разделить прямое доказательство, переносимое доказательство, предположение и недостаток информации.

## Test case 2 — Ведущий специалист по сервисной поддержке ассортимента

**Источник:** https://hh.ru/vacancy/135901970?from=share_ios

**Компания:** «МАГНИТ, Розничная сеть. Офис».

**Ключевые требования:**

- аналитический склад ума;
- большие объёмы информации;
- самообучаемость;
- Excel: ВПР и сводные таблицы;
- SQL приветствуется;
- отчётность, ассортиментные матрицы и контроль показателей;
- письменные и телефонные запросы.

**Известные данные кандидата:** Excel, iiko, учёт, отчётность, запасы, поставщики, координация процессов, самостоятельное изучение AI и публичный проект.

**Неподтверждённые данные:** ВПР, сводные таблицы, SQL, ассортиментные матрицы, сопоставимый масштаб данных, точный характер телефонных запросов.

**Критерии:**

1. Не считать общий Excel подтверждением ВПР и сводных таблиц.
2. Не считать учёт запасов прямым опытом ассортиментных матриц.
3. Отделить подтверждённую самообучаемость от обещания быстро освоить всё.
4. Не считать телефонные запросы холодными звонками без доказательств.
5. Не отклонять вакансию только из-за отсутствующей зарплаты.
6. Обосновать рекомендацию фактами соответствия, а не срочной потребностью кандидата в работе.

## Test case 3 — два независимых решения

**Сценарий:** вакансия подходит по локации и формату; подтверждены Excel, отчётность и самообучаемость; зарплата неизвестна; характер телефонных обращений неоднозначен; ВПР и сводные таблицы не подтверждены; SQL указан как желательный.

**Ожидается:**

- рекомендация `откликаться` при наличии подтверждённых релевантных совпадений;
- по принятию предложения — проверить зарплату и характер звонков;
- не считать желательный SQL стоп-фактором;
- явно перечислить неподтверждённые ВПР и сводные таблицы;
- отделить отклик от принятия предложения.

## Test case 4 — скрытый стоп-фактор

**Сценарий:** в вакансии прямо указаны ежедневные холодные звонки потенциальным клиентам. Анализатор заявляет, что звонки не указаны, рекомендует откликаться и присваивает `CONDITIONAL PASS`.

**Ожидается:**

- QA-статус `FAIL`;
- `CONDITIONAL PASS` недопустим;
- холодные звонки должны быть отмечены как подтверждённый стоп-фактор;
- пропуск считается критическим, поскольку способен изменить рекомендацию.

## Test case 5 — неизвестный обязательный SQL

**Сценарий:** зарплата 90 000 ₽, формат подходит, холодных звонков нет; уверенный SQL обязателен; уровень SQL кандидата не указан; обучение не обещано.

**Ожидается:**

- SQL — `недостаточно информации`, а не `отсутствует`;
- отклик — при условии проверки собственного уровня и ожиданий работодателя;
- по принятию предложения — пока недостаточно информации;
- анализ получает `PASS`, если неизвестность раскрыта, обязательное требование не скрыто и остальные критерии разобраны корректно.

## Test case 6 — страница вакансии недоступна

**Сценарий:** бот получил ссылку на вакансию, но страницу не удалось открыть или извлечь после временной ошибки.

**Ожидается:**

- выполнить ограниченный retry только открытия или извлечения после короткой паузы;
- после повторной ошибки сообщить пользователю, что текст вакансии получить не удалось;
- запросить текст вакансии, читаемые скриншоты или другую рабочую ссылку;
- не запускать полный AI-анализ до получения данных вакансии;
- не создавать вымышленный отчёт и не использовать `.txt` или `.md` как замену отсутствующим данным вакансии.

## Test case 7 — текст извлечён, но данных недостаточно

**Сценарий:** страница открылась, читаемый текст вакансии извлечён, но в нём не указаны зарплата, формат работы и характер телефонных обращений.

**Ожидается:**

- не считать ситуацию технической ошибкой извлечения;
- отметить зарплату, формат и характер звонков как неизвестные условия;
- не выдумывать отсутствующие сведения;
- подготовить конкретные вопросы работодателю;
- при необходимости провести только ограниченный предварительный анализ известных фактов;
- не изображать полный окончательный анализ до прохождения condition достаточности.

## Test case 8 — анализ готов, но Google Docs не сохраняет результат

**Сценарий:** AI-анализ полностью готов и прошёл QA, но Google Docs вернул временную ошибку сохранения.

**Ожидается:**

- выполнить ограниченный retry только операции сохранения;
- не повторять открытие страницы, извлечение данных, AI-анализ и QA;
- после повторной ошибки сохранить уже готовый анализ в `.txt` или `.md`;
- отправить fallback-файл пользователю;
- сообщить, что Google Docs временно не обновлён;
- при необходимости позже повторить только сохранение в Google Docs.

## Test case 9 — Make MVP: отсутствуют данные кандидата

**Сценарий:** `vacancy_text` заполнен, а mapped variable `candidate_data` имеет значение `emptystring`.

**Ожидается:**

- route `Missing input` получает один bundle;
- `Tools 6` создаёт понятный `error_message`;
- route `Both inputs present` блокирует bundle;
- `Tools 3` и `Make AI Toolkit` не выполняются;
- AI-token credits не списываются;
- сценарий остаётся `Inactive`.

## Test case 10 — Make MVP: оба input заполнены

**Сценарий:** mapped variables `vacancy_text` и `candidate_data` заполнены синтетическими тестовыми данными.

**Ожидается:**

- route `Missing input` блокирует bundle;
- route `Both inputs present` получает один bundle;
- `Tools 3` создаёт `validation_status`;
- `Make AI Toolkit` запускается ровно один раз;
- Output содержит текстовый `Answer`;
- технический успех оценивается отдельно от смыслового QA ответа.

## Test case 11 — QA gate: ручная проверка

**Сценарий:** Medium AI вернул ответ, в котором отсутствуют шесть известных запрещённых паттернов.

**Ожидается:**

- route `Known QA violation` блокирует bundle;
- `Tools 12` с `qa_status = FAIL` не выполняется;
- fallback `Manual review required` получает один bundle;
- `Tools 13` создаёт `qa_status = MANUAL_REVIEW`;
- отсутствие известных паттернов не превращается в автоматический semantic `PASS`.

## Test case 12 — QA gate: известное нарушение

**Сценарий:** во время контролируемого теста в filter временно добавлен паттерн `Статус данных`, гарантированно присутствующий в формате AI-ответа.

**Ожидается:**

- route `Known QA violation` получает один bundle;
- `Tools 12` создаёт `qa_status = FAIL` и блокирующее сообщение;
- fallback `Manual review required` и `Tools 13` не выполняются;
- после теста временный паттерн удаляется, остаются только production-проверки.

## Тест-кейс 13 — первоначальная блокировка Telegram-команды до welcome route

```text

```

- trigger получил `1` update;
- command filter пропустил `0` bundles;
- все downstream-модули остались заблокированы;
- AI analysis credits не списывались.

### Вердикт

```text
PASS
```

## Тест-кейс 17 — Telegram FAIL на текущей Router-архитектуре

### Подготовка

Во временный конец `Known QA violation` добавлено отдельное OR-условие:

```text
4.Answer
Contains (case insensitive)
Статус данных
```

### Ожидание

- обычный текст проходит current vacancy route и запускает AI;
- guaranteed pattern направляет Answer только в `FAIL`;
- `MANUAL_REVIEW` не выполняется;
- Telegram отправляет только блокирующее сообщение, не AI Answer;
- временное условие после теста удаляется без повторного запуска.

### Фактический результат

```text
Duration: 17 seconds
Operations: 6
Credits: 6.85
Data size: 5.7 KB
```

Выполнились trigger, input Tools, success Tools, AI, FAIL Tools и Telegram FAIL delivery. Missing-input, command и `MANUAL_REVIEW` routes были заблокированы.

Полученный текст:

```text
❌ FAIL

Ответ заблокирован: обнаружена запрещённая или служебная формулировка. Нужна ручная проверка.
```

Временный `Статус данных` удалён; постоянные patterns сохранены. Сценарий сохранён без нового AI-run.

### Вердикт

```text
PASS
```
